# MapMarker 단계별 계획

> 최종 갱신: 2026-11-19 · 큰 그림과 결정 이유는 [OVERVIEW.md](OVERVIEW.md)
>
> 각 단계는 **완료 기준**을 만족해야 끝나고, 모든 완료 기준에 **테스트 통과**(서버 Jest, 앱 `flutter test`)가 들어간다. 인프라를 바꿀 때는 `문제 → 측정 → 설계 → 적용 → 검증`을 `docs/`에 기록한다.

## 전체 흐름

| 단계 | 이름 | 핵심 |
|---|---|---|
| 0 | 준비 | 계정, API 키, 저장소, 앱 구조, 이미지 내보내기 기술 검증 |
| 1 | **MVP** | 국내 여행 핵심 기능 + AWS 단일 서버 + Play Store 출시 |
| 2 | 해외 · AI | 구글 지도와 Places, 오프라인 보기, AI 동선 생성, 푸시, 지출과 정산 |
| 3 | 공유 링크 | 도메인, 앱 링크, 스토어 이동, 읽기 전용 보기, 공유 끄기, 내 여행으로 복사 |
| 4 | 트래픽 확장 | 부하 테스트 → ALB → Auto Scaling |
| 5 | 운영 고도화 | 캐시, DB 인덱스, CI/CD, 모니터링, 비용 최적화 |
| 6 | iOS | 맥이 있는 친구와 iOS 빌드와 출시, Apple 로그인 |
| 7 | 확장 기능 | GPS 기록, 이미지 직접 편집, deferred deep link, 영수증 인식 |

3~6단계의 순서는 바꿀 수 있다(예: CI/CD는 앞당겨도 된다).

## 0단계. 준비

- [x] GitHub 조직과 저장소 4개(2단계 인증, noreply 이메일, Secret scanning·Push protection)
- [x] 서버 NestJS + Prisma + 로컬 PostgreSQL(Docker), 테스트 기본 설정(서버 Jest 단위 + e2e, 앱 `flutter test`)
- [x] 네이버 지도 SDK 키, 카카오·네이버 로그인 앱 등록
  - 카카오: 로그인과 **OpenID Connect**, 동의 항목은 닉네임만(선택). 네이티브 앱 키는 서버 `KAKAO_NATIVE_APP_KEY`에. 키 해시는 지금 개발 PC의 debug 것만 있다
  - 네이버: 별명만(추가 제공), 서버에 넣을 값은 없다
- [x] AWS 계정: 루트 MFA, IAM 사용자, **Budget 알림**(1-3 시작 때)
- [x] Flutter 앱 구조: Riverpod(코드 생성 없이), go_router, `data/`·`core/`와 `features/`. 모든 화면 경로를 여행 목록 아래에 둔다(공유 링크로 열어도 뒤로가기가 목록으로)
- [x] **이미지 내보내기 기술 검증(앱 PR #1):** 네이버 SDK 스냅샷(`takeSnapshot`) 위에 Flutter Canvas로 선·마커·사진을 합성한다. Static Map API는 쓰지 않는다
  - 지도 위젯을 결과 크기(가로 1080px ÷ 기기 픽셀 비율)로 띄워 1:1, 4:5, 9:16을 한 장으로 얻는다(이어 붙이면 이음새에서 글자가 잘린다)
  - **네이버 로고는 끄거나 가리면 안 된다.** 왼쪽 아래에 고정하고 합성 뒤 로고 영역을 원본으로 다시 덮는다
  - 검증 화면은 디버그 빌드에만 두고 1-5 미리보기가 생기면 지운다

**완료 기준:** 앱과 서버가 로컬에서 돌고, 지도·로그인 키, 앱 구조, 이미지 내보내기 방식이 정해져 있다.

## 1단계. MVP (Android, 국내, AWS 단일 서버)

### 1-1. 서버 기본

- [x] NestJS 구조와 Swagger(`/v1`, 운영에서는 `/docs`를 닫는다), Prisma 스키마(앱 규칙을 DB 제약으로도 막고 e2e로 확인)
- [x] **CI(5단계에서 앞당김):** push·PR마다 lint·형식·단위·빌드·e2e. `main`은 PR로만 병합하고 CI 통과 필요
- [x] 자체 JWT 인증, Trip / Stop / Segment CRUD(앱 ID UUID v7, 중복 409, 남의 것 404, 구간은 서버가 앱과 같은 규칙으로 잇는다)
- [x] 카카오·네이버 로그인: 제공자 토큰 검증 → 사용자 찾기·만들기 → 자체 access·refresh 토큰, 재발급(교체)·로그아웃

### 1-2. 앱: 지도와 동선 편집

- [x] 다국어(한국어), 디자인 토큰(코랄, 나눔스퀘어라운드, 라이트), `MapProvider`와 네이버 구현
- [x] 여행 목록(카드 격자)과 만들기, 기본 제목, 상태 표시와 직접 변경
- [x] 여행 동선 페이지(일차별·전체, 일차 색, 출발 장소, 숙소 끄기와 "숙소를 거침" 선), 일차 동선 시트(넓은 화면은 오른쪽 패널)
- [x] 장소 추가(지도 탭)·편집·순서·삭제, 연박, 구간 이동 수단(토막 최대 5개, 선 모양과 아이콘), 곡선 핸들과 진행 방향 화살표
- [x] 서버 연동과 로그인 화면, 저장 중 표시와 실패 안내, 당겨서 새로고침
- [x] 제주 샘플 여행(보기 전용, [실제로 사용하기]로 복사)
- [x] **휴지통:** 서버 `deletedAt`과 `/v1/trash`(되살리기, 영구 삭제, 30일 지난 여행 예약 삭제), 앱 휴지통 화면. 대상은 여행만(샘플은 기기에서 숨김), 탈퇴는 바로 삭제(1-6), 휴지통 여행은 공유 링크가 열리지 않는다(3단계)

### 1-2 후속. 후보 장소

갈지 정하지 않은 장소를 여행마다 모은다(OVERVIEW "후보 장소").

- [x] 서버: 장소와 따로 된 후보 테이블, **동선에 넣기**와 **후보로 빼기**(한 트랜잭션, 같은 ID)
- [x] 앱: 칩 두 줄(보기와 "함께 보기" 필터), [후보로 저장], "후보 목록" 보기, [동선에 넣기]와 [후보로 빼기], 샘플 후보 3곳

### 1-2 후속. 장소 검색과 동선 사이 +

지도 앱에서 찾은 곳을 주소로 가져와 넣는다. 지도 누르기는 주소로 못 찾는 곳(해변, 오름)용으로 남긴다(OVERVIEW "지도, 외부 서비스, AI").

- [x] 설계: **주소(또는 건물명) 한 줄 + 행안부 도로명주소 API**(다른 API는 약관이 결과 저장을 막는다)
- [x] 서버: 장소·후보 `address`, `GET /v1/addresses`(검색어 다듬기, 상세 주소, 최대 10건)와 `/coordinates`(UTM-K → WGS84)
- [x] 앱: 주소 칸(검색 칸을 겸해 위치도 옮긴다), 동선 사이 ⊕, "장소 넣기", "후보 찾아 넣기", 샘플 주소. "넣을 자리" 칸은 없앴다

### 1-3. 사진

장소마다 1장(없어도 된다, 나중에 여러 장). 설계 이유는 OVERVIEW "사진, 이미지, 공유".

- [x] 개발용 S3 버킷(퍼블릭 차단, 버전 관리 끔, 등록하지 않은 파일을 하루 뒤 지우는 수명 주기 규칙), 서버용 IAM 사용자(버킷의 `users/*`만)
- [x] 서버: 업로드 URL 발급(10분, JPEG와 바이트 수를 서명), 등록(있으면 바꾸기), 지우기, 장소 응답에 사진 URL(1시간 GET 서명)
- [x] 앱: 원본으로 줄이고 EXIF를 지운 뒤 "사진 위치" 화면에서 고른 정사각형으로 썸네일을 만들어 S3에 직접 올린다. 장소 줄과 지도 마커(둥근 사각 사진)에 썸네일, 누르면 크게 보기
- [x] 후보로 빼면 사진을 지우고(확인 창에 알림), 사진·장소 삭제와 영구·예약 삭제 때 S3 파일도 지운다(휴지통으로 옮길 때는 아니다)
- CloudFront로 사진 제공은 1-7로 옮겼다(앱은 그대로, 서버의 URL 서명만 바꾼다)

### 1-4. 여행 중 기능

여행 중에 지도와 시트에서 쓰는 것. 설계 이유는 OVERVIEW "여행 중".

- [x] 현재 위치 표시("앱 사용 중" 위치 권한만)와 근처의 후보 장소(위치를 알면 후보 목록이 가까운 순, 거리 표시)
- [x] 방문 체크, 실제 방문 시각(현지 시간대와 함께): 서버 PATCH `visitedAt`, 장소 줄의 방문 동그라미와 확인 창, 장소 편집의 방문 날짜와 시각
- [x] 여행 중이면 오늘 일차로 열기, 앞 일차 숙소로 돌아가는 [오늘 밤은 ○○에서 묵기], 시트를 따라 올라가는 지도 버튼, 칩 두 줄 접기

### 1-5. 이미지 내보내기 (핵심 기능 Top 2)

- [ ] 0단계 방식으로 지도 위에 동선, 이동 수단, 화살표, 장소 이름, 사진 썸네일, 제목을 합성한다
- [ ] **항상 최신 여행 데이터로 만든다.** 이미지 위 편집(텍스트, 스티커, 배치)은 넣지 않는다
- [ ] 상태별 표현: 전은 계획 동선, 중은 방문한 곳과 남은 곳, 후는 사진 중심 회고
- [ ] 옵션: 범위(전체 / 일차), 비율(1:1, 4:5, 9:16), 사진, 숙소, 제목 문구. 후보는 기본으로 넣지 않고 옵션은 이때 정한다
- [ ] 미리보기에서 옵션을 바꾸며 확인하고, 갤러리 저장과 `share_plus` 공유

### 1-6. 계정

- [x] 로그아웃(지금은 여행 목록 `⋮`, 설정 화면이 생기면 옮긴다)
- [ ] **회원 탈퇴:** 앱 안에서 여행(휴지통 포함), 장소, 사진(S3)까지 휴지통 없이 모두 지운다
- [ ] 앱 밖 계정 삭제 요청 웹 페이지(Google Play 정책, S3 + CloudFront)
- [ ] 설정 화면의 "샘플 여행 다시 보기"(지금은 앱 데이터를 지워야 보인다)

### 1-7. AWS 배포 (단일 서버)

- [ ] VPC, Security Group, IAM 역할(NAT Gateway는 쓰지 않는다), EC2 1대 + RDS + S3 + CloudFront, CloudWatch 기본 로그
- [ ] 사진을 CloudFront 서명 URL로 제공(1-3에서 옮겼다): 운영 버킷, OAC, 키 그룹, 서버의 서명 비밀키. 서버는 IAM 액세스 키 대신 EC2 역할
- [ ] 앱이 운영 서버를 보도록 환경을 나눈다(dev / prod). debug 빌드에 `applicationIdSuffix = ".dev"`를 주고 카카오·네이버 로그인과 네이버 지도 콘솔에 `.dev` 패키지를 다시 등록한다
- [ ] 행안부 주소 API를 운영 승인키로 바꾸고(개발키는 기간이 끝나면 주소 검색이 500) 운영키 조건과 하루 호출 한도를 확인한다

### 1-8. Play Store 출시

출시 경험이 있어서 이 앱에서 새로 챙길 것만 적는다.

- [ ] **개인정보처리방침**과 공개 URL: 위치, 사진, 소셜 로그인 정보의 수집 항목, 목적, 보관 기간(휴지통 30일, 탈퇴는 바로), 삭제 방법. 받는 것은 제공자 사용자 ID(앱별)와 닉네임(선택)이고 카카오 동의 화면의 닉네임 목적과 맞춘다. 위치 권한과 사진은 정책과 예시를 자세히 조사한다
- [ ] 카카오 콘솔에 release 키와 Play 앱 서명 키의 키 해시(없으면 출시 빌드에서 카카오 로그인 실패)
- [ ] Play Console 데이터 보안(위치, 사진, 계정), 위치 권한 사용 목적 설명, 계정 삭제 웹 페이지 URL
- [ ] 비공개 테스트 요건을 확인해 테스트한 뒤 정식 출시(신규 계정 기준이 있으면 테스터를 미리 모은다)

**완료 기준:** Play Store의 Android 앱으로 국내 여행을 처음부터 끝까지 쓴다. 여행 목록 → 동선 페이지 → 시트와 네이버 지도 연결 → 여행 중 체크 → 사진 → 이미지 공유가 되고, 탈퇴가 되며, 서버는 AWS에서 돈다.

## 2단계. 해외 · AI

### 2-1. 구글 지도와 Places

- [ ] `MapProvider`의 구글 구현과 여행 단위 지도 자동 전환(모두 국내면 네이버, 하나라도 해외면 구글, 설정에서 바꿀 수 있다)
- [ ] `PlaceSearchProvider`: 국내는 1-2 후속의 행안부 주소 검색, 해외는 Google Places 자동완성(네이버 검색은 결과를 저장할 수 없어 쓰지 않는다). Stop에 `placeId`
- [ ] 장소를 넣을 때 좌표로 현지 시간대를 정한다
- [ ] "구글 맵에서 열기" 칸(placeId가 있으면 정확한 장소로)
- [ ] 날짜변경선을 넘는 구간의 곡선 처리
- [ ] Places 과금과 무료 한도를 확인하고 서버에서 호출량을 기록한다

### 2-2. 오프라인 보기

- [ ] 마지막으로 불러온 여행(장소, 구간, 후보, 설명)을 기기에 저장하고, 끊기면 그것으로 여행 중 화면을 보이며 오프라인임을 표시한다
- [ ] 오프라인 방문 체크를 저장했다가 연결되면 보낸다. 2-5 지출도 같은 방식이라 여러 종류의 쓰기를 담게 만든다
- 지도 타일의 오프라인 저장은 SDK 약관과 지원을 확인한 뒤 정한다

### 2-3. AI 동선 생성

- [ ] 입력은 여행지, 계절, 일정. 서버가 LLM을 불러 구조화된 JSON(일차별 장소 이름, 순서, 이동 수단, 메모)을 받는다
- [ ] **장소 이름을 Places로 검색해 좌표를 검증한다.** 검색되지 않으면 빼거나 표시한다
- [ ] 결과는 일반 Trip(계획 상태, 출처 AI)이라 바로 편집한다. 대안 장소를 후보로 넣을지 정한다
- [ ] 비동기 작업 큐(BullMQ 또는 SQS), 작업 ID 응답, **FCM 푸시** "동선이 완성됐어요"
- [ ] 운영 장치: 사용자별 횟수 제한, 같은 입력 캐싱, 프롬프트 버전 관리, 재시도, 비용 기록
- [ ] 처리방침에 AI 처리와 푸시 알림을 더한다

### 2-4. 회고

- [ ] 계획과 실제 비교(예정 vs 실제 시각, 계획에 없던 장소)

### 2-5. 지출 기록

해외(2-1)의 통화와 오프라인(2-2)이 먼저다. 설계 이유는 OVERVIEW "지출 기록과 동행 정산".

- [ ] 서버: 지출 = 금액(통화의 최소 단위 정수), 통화(ISO 4217), 결제 수단(현금/카드/교통카드/기타), 메모, 날짜. 장소나 여행에 붙인다. 여행마다 기준 통화(기본 KRW), 지출마다 환산 금액, 쓴 환율, 환율 출처(그날 / 직접)
- [ ] 서버: 환율 API를 하루 단위로 캐시한다(API와 약관은 시작할 때 확인)
- [ ] 앱: 장소 줄의 지출, 장소 없는 지출 목록, 일차·여행 합계(통화별, 기준 통화), "현재 환율로 보기"(화면에서만 계산), 오프라인 지출(2-2)
- [ ] 2-4 회고에 지출 합계를 넣을지 정한다

### 2-6. 동행 정산

- [ ] 동행은 여행마다 이름 목록(계정 아님, "나"가 기본). 입력은 주인만, 친구는 3단계 공유 링크로 본다
- [ ] 지출마다 낸 사람(동행 또는 공금)과 함께 쓴 사람(기본은 똑같이 나눔. 금액 직접 나누기는 나중에)
- [ ] 공금: 넣은 돈, 공금 지출, 남은 돈
- [ ] 정산: 사람마다 낸 돈과 쓴 돈의 차이를 기준 통화로 구해 누가 누구에게 얼마를 보낼지 적은 횟수로 보여 준다

**완료 기준:** 해외 여행도 장소를 검색해 계획하고, 끊겨도 여행 중 화면을 보며, AI 동선이 검증된 좌표로 만들어져 푸시로 알려 준다. 여러 통화의 지출을 기록하고 정산한다.

## 3단계. 공유 링크

- [ ] Route 53 도메인, 공유 링크 `https://<도메인>/trip/<공유ID>`(링크가 있는 사람만 열람)
- [ ] Android App Links(`assetlinks.json`을 S3 + CloudFront로), 앱이 없으면 스토어로 보내는 페이지
- [ ] 링크를 받으면 **읽기 전용**으로 연다(로그인 필요, 편집 숨김). 동선, 설명, 사진은 보이고 메모는 서버 응답에서부터 뺀다. 정할 것: 후보(제안: 보이고 메모는 숨김), 지출·정산(제안: 주인이 켠다)
- [ ] **공유 끄기 / 링크 새로 발급:** 끄면 공유 ID를 비우고, 새로 발급하면 바꾼다. 휴지통 여행은 열리지 않고 되살리면 다시 열린다
- [ ] **내 여행으로 복사:** 서버가 공유 ID로 Trip, Stop, Segment를 새로 만들고 출처 "복사"와 원본을 기록한다. 복사본은 원본과 연결되지 않고 "여행 전"으로 시작한다(복사 범위는 OVERVIEW. 후보는 이때 정한다, 제안: 넣는다. 지출·동행은 넣지 않는다). 앱은 복사 버튼, 끝나면 내 목록에서 바로 편집

**완료 기준:** 링크를 누르면 앱이 있으면 읽기 전용으로 열리고(메모 제외), 없으면 스토어로 간다. 공유를 끄거나 새로 발급하고, 공유받은 여행을 복사해 고친다.

## 7단계. 확장 기능 (아이디어)

- GPS 기록 세션: 백그라운드 위치(Android Foreground Service, iOS 백그라운드 모드)라 심사와 처리방침 설명이 더 필요하다. 점은 Douglas-Peucker로 줄이고 오래 머문 곳은 Stop 후보로, 구간은 "GPS 트랙" Segment
- 이미지 위 직접 편집(텍스트, 스티커, 배치): 편집 상태를 따로 저장해야 한다
- Deferred deep link: 설치 직후 공유받은 여행을 바로 연다
- 장소 정보(트리플처럼 영업시간, 사진, 소개): Google Places UI Kit이나 TourAPI로 보여 줄지 따로 정한다. 하려면 OVERVIEW의 "장소 정보는 앱이 보여 주지 않는다" 결정과 각 약관부터 다시 본다
- 영수증 인식: 금액·통화·날짜를 채우고 사용자가 확인한다. 기기 안 글자 인식(ML Kit)과 서버 AI 중에 고른다. 상호·카드 번호 일부가 있어 처리방침에 넣는다
- 모바일 웹(지금은 고려하지 않음)
