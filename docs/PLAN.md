# MapMarker 단계별 계획

> 최종 갱신: 2026-10-21 · 큰 그림과 결정 이유는 [OVERVIEW.md](OVERVIEW.md) 참고
>
> 각 단계는 **완료 기준**을 만족해야 끝난 것으로 본다. 모든 단계의 완료 기준에는 **테스트 통과**(서버 Jest, 앱 `flutter test`)가 포함된다. 인프라를 바꿀 때는 `문제 → 측정 → 설계 → 적용 → 검증`을 `docs/`에 기록한다.

## 전체 흐름

| 단계 | 이름 | 핵심 |
|---|---|---|
| 0 | 준비 | 계정, API 키, 저장소, 앱 구조 결정, 이미지 내보내기 기술 검증 |
| 1 | **MVP** | 국내 여행 기준 핵심 기능 + AWS 단일 서버 배포 + Play Store 출시 |
| 2 | 해외 · AI | 구글 지도와 Places, 오프라인 보기, AI 동선 생성, 푸시 알림 |
| 3 | 공유 링크 | 도메인, 앱 링크, 스토어 이동, 읽기 전용 보기, 공유 끄기, 내 여행으로 복사 |
| 4 | 트래픽 확장 | 부하 테스트 → ALB → Auto Scaling |
| 5 | 운영 고도화 | 캐시, DB 인덱스, CI/CD, 모니터링, 비용 최적화 |
| 6 | iOS | 맥이 있는 친구와 함께 iOS 빌드와 출시, Apple 로그인 추가 |
| 7 | 확장 기능 | GPS 기록 세션, 이미지 직접 편집, deferred deep link |

3~6단계의 순서는 상황에 따라 바꿀 수 있다. 예: CI/CD는 앞당겨도 된다.

## 0단계. 준비

- [x] GitHub 조직 `mapmarker-dev`와 저장소 4개(`.github`, `mapmarker-app`, `mapmarker-server`, `mapmarker-web`) 만들기
- [x] 공통 규칙(`.github/CLAUDE.md`)과 기획 문서를 `.github` 저장소로 옮기기
- [ ] GitHub 설정: 2단계 인증, 커밋 이메일을 noreply 주소로 설정, 저장소별 Secret scanning·Push protection 켜기
- [ ] `mapmarker-server`에 NestJS + Prisma 프로젝트 만들기. `.env`가 `.gitignore`에 있는지 첫 커밋 전에 확인한다. `CLAUDE.md`에 공통 규칙 불러오기와 서버 명령어를 쓴다
- [x] 네이버 클라우드 플랫폼: 지도 SDK 키 발급
- [ ] 네이버 개발자센터 / 카카오 개발자: 소셜 로그인 앱 등록
- [ ] AWS 계정: 루트 계정 MFA 설정, IAM 사용자 생성, **Budget 알림 설정**
- [ ] 로컬 개발 환경: Docker로 PostgreSQL 실행
- [x] **Flutter 앱 구조 결정**: 상태 관리, 라우팅(3단계 딥링크 처리 고려), 폴더 구조
  - 상태 관리: **Riverpod** (코드 생성 없이). 저장소는 인터페이스로 두고, 서버 API가 생기기 전에는 메모리 구현으로 화면을 만든다
  - 라우팅: **go_router**. 공유 링크 `/trip/<공유ID>`는 앱 안에서 redirect로 읽기 전용 화면 경로에 연결한다. 모든 화면 경로를 여행 목록 아래에 둬서, 링크로 바로 열어도 뒤로가기가 여행 목록으로 간다
  - 폴더 구조: 모델·저장소는 공용 `data/`, 화면과 상태는 기능별 `features/`, 지도 인터페이스와 곡선 계산은 `core/`. 거의 모든 기능이 같은 Trip 묶음(Trip·Stop·Segment·Photo)을 다루기 때문이다
  - 이미지 내보내기 검증 화면은 디버그 빌드에서만 열리게 남겨 두고(지도 SDK·Flutter를 올릴 때 다시 확인하는 용도), 1-5단계 미리보기 화면이 생기면 지운다
- [ ] 테스트 기본 설정: 서버 Jest(단위 + e2e), 앱 `flutter test`(단위 + 위젯)
- [x] **이미지 내보내기 기술 검증 (프로토타입)**: 핵심 기능 Top 2이고 기술 위험이 가장 큰 부분이라 먼저 확인한다 (앱 저장소 PR #1)
  - 질문: 네이버 지도 SDK 스냅샷으로 지도 이미지를 얻고, 그 위에 선·마커·사진을 합성해 고해상도 PNG로 저장할 수 있는지
  - **결정: SDK 스냅샷(`takeSnapshot`) 위에 Flutter Canvas로 직접 합성한다.** Static Map API 대안은 쓰지 않는다
    - 좌표는 `latLngToScreenLocation`으로 이미지 위치로 바꾼다. 실제 기기에서 지도 위 위치와 정확히 겹치는 것을 확인했다
    - 곡선은 화면 좌표에서 2차 베지어로 계산한다. 화면 좌표가 이미 메르카토르 투영이라 결과가 같다
    - SDK 오버레이(마커·선)도 스냅샷에 찍히지만, 곡선·화살표·사진을 자유롭게 그리려고 직접 그린다
  - **해상도: 지도 위젯을 결과 크기(가로 1080px ÷ 기기 픽셀 비율)로 띄우고, 화면에는 `FittedBox`로 줄여 보여 준다**
    - 휴대폰·태블릿 모두 1:1(1080×1080), 4:5(1080×1350), 9:16(1080×1920) 스냅샷을 한 번에 얻는다
    - 여러 장을 이어 붙이는 방식은 이음새에서 지도 글자가 잘리고 느려서 쓰지 않는다
    - 지도가 다른 위젯에 가려져 있어도 스냅샷이 찍힌다 (미리보기 뒤에 지도를 숨겨 둘 수 있다)
  - 사진 썸네일: 장소별로 가운데를 잘라 둥근 모서리로 그린다. 사진이 없는 장소는 비워 둔다
  - **네이버 로고는 끄거나 가리면 안 된다.** 로고를 왼쪽 아래에 고정하고, 합성이 끝난 뒤 로고 영역을 원본 스냅샷으로 다시 덮는다

**완료 기준:** 앱과 서버가 각각 로컬에서 실행되고, 지도 키와 로그인 키가 준비돼 있고, 앱 구조와 이미지 내보내기 방식이 정해져 있다.

## 1단계. MVP (Android, 국내, AWS 단일 서버)

### 1-1. 서버 기본

- [ ] NestJS 프로젝트 구조 잡기 (Module / Controller / Service), Swagger 설정
- [ ] Prisma 스키마 작성: User, Trip, Stop, Segment, Photo
  - ID: 앱이 만든 UUID v7을 그대로 쓴다 (형식 검사, 이미 있으면 409). 공유 ID만 서버가 만든다
  - Trip: 기간(시작일·종료일 `date`, 없을 수 있음), 직접 바꾼 상태(없으면 자동)
  - Stop: 예정 시각(일차 + 현지 시:분 `time`), 실제 시각(`timestamptz`)과 **시간대**(예: `Asia/Seoul`), `placeProvider`·`placeId`(선택 필드로 미리 둔다)
  - Segment: 이동 수단 목록(수단, 정류장 수, 걸리는 시간), 곡률 `k`, 타입(일반 / GPS 트랙)
- [ ] 카카오·네이버 로그인
  - 앱이 받은 토큰을 서버가 검증하고, 서버가 자체 JWT(access, refresh)를 발급한다
- [ ] Trip / Stop / Segment CRUD API, 입력 검증(DTO)
- [ ] 여행 상태: 직접 바꾼 상태만 저장한다. 자동 상태(전/중/후)는 앱이 기기 날짜로 계산한다 (서버는 사용자의 시간대를 모른다)

### 1-2. 앱: 지도와 동선 편집

- [x] 다국어 구조: gen-l10n, 한국어 ARB. 영어는 나중에 추가한다
- [x] 디자인 토큰: 기본 값 → 의미 토큰 → 컴포넌트 테마, 주 색 코랄, 나눔스퀘어라운드, 라이트 모드 먼저
- [x] `MapProvider` 인터페이스를 만들고 네이버 지도로 구현한다
- [x] **여행 목록 화면**: 정사각형 카드 격자 (휴대폰 2열, 태블릿 3~4열). 카드에는 상태, 제목, 기간과 일정
- [x] 여행 생성: 지역(필수), 기간(선택) 입력
  - 기간을 넣으면 일정(몇 박 몇 일)·계절·상태를 기간으로 자동으로 채운다. 기간이 없으면 일정과 계절을 직접 고르고, 상태는 "전"으로 둔다
  - 기본 제목은 "{지역} {일정} {계절} 여행"이다 (예: "부산 2박 3일 봄 여행", "경주 당일치기 가을 여행"). 사용자가 언제든지 바꿀 수 있다
- [x] 여행 상태 표시(전/중/후)와 직접 변경, 자동으로 되돌리기
- [x] **여행 동선 페이지**: 동선을 따라 지도 표시. 일차별 보기와 여행 전체 보기를 전환한다
  - 일차는 선과 마커 색으로 구분하고, 마커에는 일차 안 번호와 종류 아이콘이 있다
  - 일차 보기는 전날 숙소에서 출발한다. 숙소를 켜고 끌 수 있다
- [x] 지도를 탭해서 Stop 추가, 이름·종류·설명·메모·예정 시각 입력, 순서 변경, 삭제
  - 종류: 숙소·음식·관광·기타(기본). 연박하면 "어제 숙소 그대로"로 같은 숙소를 한 번에 넣는다(일차 동선 시트의 "오늘 밤도 ‹숙소›에서 묵기")
  - 지도 빈 곳을 누르면 임시 핀을 띄우고 확인한 뒤 입력 화면을 연다. 네이버 지도의 장소 이름(심볼)을 누르면 이름을 채운다
  - 새 장소는 그 일차 맨 뒤에 넣는다. 마지막이 숙소면 숙소 바로 앞에 넣는다(숙소는 그날 밤 묵는 곳이라 마지막에 남는다)
- [x] **일차 동선 시트**: 일차를 고르면 그날의 장소와 구간이 차례로 나온다. 세로·좁은 화면은 지도 아래 시트, 가로이고 폭 600dp 이상이면 지도 오른쪽 패널
  - 장소 행: 이름, 종류, 예정 시각, 설명, 메모(펼치면), 사진(1-3단계). "네이버 지도에서 열기" 칸 (이름과 좌표로 검색 링크 생성)
  - 구간 행: 이동 수단 (정하지 않았으면 "미정")
  - 끌어서 순서 바꾸기, 삭제
  - 지도의 마커·선을 누르면 그 일차로 들어가 해당 행을 보여 준다. 같은 자리의 장소는 마커 하나로 합친다
  - 주소는 서버 연동 때 넣는다 (네이버 검색·역지오코딩 API는 비밀 키가 필요해서 서버를 거친다). `Stop`에 주소 칸을 둘지도 그때 정한다
- [ ] 이웃한 Stop 사이의 Segment(저장소가 자동으로 만든다)에 이동 수단 선택 (아이콘과 선 모양. 색은 일차가 쓴다)
  - 수단(도보·지하철·버스·기차·차·비행기·배)과 정류장 수·걸리는 시간을 적고, 갈아타면 여러 수단을 잇는다 (예: 지하철 2정류장 + 도보, 비행기 3시간 20분). 이동 수단은 고르지 않아도 된다(미정)
- [ ] **곡선 구간**
  - 구간을 선택하면 중간에 핸들이 나타나고, 드래그로 곡률 `k`를 조절한다
  - 2차 베지어 곡선을 메르카토르 좌표로 계산해 폴리라인으로 그린다
- [x] 진행 방향 화살표 표시 (구간 가운데에 하나. 선이 화면에서 짧으면 숨긴다)
- [ ] 서버 API 연동, 로그인 화면

### 1-3. 사진

장소마다 사진은 1장이다. 사진이 없는 장소도 있다. 나중에 여러 장으로 늘어날 수 있다.

- [ ] 서버: S3 Presigned URL 발급 API (로그인·여행 소유자 확인, 저장 경로 지정, 짧은 유효 시간, 파일 형식·크기 제한)
- [ ] 앱: 업로드 전에 사진 크기를 줄이고 위치 정보(EXIF)를 지운다. 촬영 시각·좌표는 따로 저장하지 않는다
- [ ] 앱: 발급받은 URL로 S3에 직접 업로드한 뒤, 서버에 업로드 완료를 알려 Photo로 등록하고 Stop에 연결한다
- [ ] 지도 마커에 썸네일을 표시한다
- [ ] CloudFront로 사진 제공
- [ ] **삭제 처리**: 사진·장소·여행을 지우면 연결된 S3 파일도 지운다

### 1-4. 여행 중 기능

- [ ] 현재 위치 표시 ("앱 사용 중" 위치 권한만 사용)
- [ ] Stop 방문 체크, 실제 방문 시각 기록 (현지 시간대와 함께)

### 1-5. 이미지 내보내기 (핵심 기능 Top 2)

여행 전·중·후 언제든 만들고, 다시 만들고, 수정한다.

- [ ] 0단계에서 검증한 방식으로 지도 위에 동선, 이동 수단, 진행 방향 화살표, 장소 이름, 사진 썸네일, 제목을 합성한다
- [ ] **항상 최신 여행 데이터로 생성한다**: 여행을 수정하면 다음에 만드는 이미지에 그대로 반영된다
  - 이미지 위에서 따로 편집하는 기능(텍스트, 스티커, 배치)은 넣지 않는다
- [ ] 여행 상태에 맞는 표현
  - 전: 계획 동선
  - 중: 방문한 곳과 남은 곳 구분
  - 후: 사진 중심 회고
- [ ] 내보내기 옵션
  - 범위: 전체 / 일차별
  - 비율: 1:1, 4:5, 9:16(스토리)
  - 사진 포함 여부, 숙소 포함 여부, 제목 문구
- [ ] 미리보기 화면에서 옵션을 바꾸며 확인한 뒤 저장한다
- [ ] 갤러리에 저장하고, `share_plus`로 공유한다

### 1-6. 계정

- [ ] 로그아웃
- [ ] **회원 탈퇴**: 앱 안에서 계정 삭제. 여행, 장소, 사진(S3)을 포함한 사용자 데이터를 모두 지운다
- [ ] 앱 밖에서 계정 삭제를 요청할 수 있는 웹 페이지 (Google Play 정책). S3 + CloudFront 정적 페이지로 만든다

- [ ] EC2 1대(NestJS) + RDS PostgreSQL + S3 + CloudFront

- [ ] 앱이 운영 서버를 바라보도록 환경을 분리한다 (dev / prod)

### 1-8. Play Store 출시

출시 경험이 있으니 이 앱에서 새로 챙길 부분 위주로 적는다.

- [ ] **개인정보처리방침** 작성과 공개 URL 준비 (S3 + CloudFront)
  - 위치, 사진, 소셜 로그인 정보를 다루므로 수집 항목, 이용 목적, 보관 기간, 삭제 방법을 담는다
  - 위치 권한과 사진 처리는 처음이라, 작성할 때 정책과 예시를 자세히 함께 조사한다
- [ ] Play Console **데이터 보안** 섹션 작성 (위치, 사진, 계정 정보)

## 2단계. 해외 · AI

### 2-1. 구글 지도와 Places

- [ ] `MapProvider`의 구글 구현을 추가한다

  - placeId로 서버를 거쳐 조회한다. Places 데이터를 DB에 저장(캐싱)해도 되는지는 약관을 확인한다

  - 규칙: Stop이 모두 국내면 네이버, 하나라도 해외면 구글
  - 여행 설정에서 사용자가 직접 바꿀 수 있다
- [ ] 날짜변경선을 넘는 구간의 곡선 처리
- [ ] Places 과금 체계와 무료 한도를 확인하고, 서버에서 호출량을 기록한다

### 2-2. 오프라인 보기

- [ ] 마지막으로 불러온 여행 데이터(장소, 구간, 설명)를 기기에 저장한다
- [ ] 인터넷이 끊기면 저장된 데이터로 여행 중 화면을 보여 주고, 오프라인 상태임을 표시한다
- [ ] 오프라인에서 한 방문 체크는 저장해 두었다가 연결되면 서버에 보낸다
- 지도 타일의 오프라인 저장은 지도 SDK 약관과 지원 여부를 확인한 뒤 정한다

### 2-3. AI 동선 생성

- [ ] 입력: 여행지, 계절, 일정(예: 3박4일)
- [ ] 서버가 LLM을 호출한다. 출력은 구조화된 JSON: 일차별 장소 이름, 순서, 구간 이동 수단, 메모
- [ ] **장소 이름을 Places로 검색해 좌표를 검증한다.** 검색되지 않는 장소는 제외하거나 표시한다
- [ ] 결과를 일반 Trip(계획 상태, 출처 AI)으로 저장해서 바로 편집할 수 있게 한다
- [ ] 비동기 작업 큐로 처리한다 (BullMQ 또는 SQS). 요청하면 작업 ID를 돌려준다
- [ ] **FCM 푸시 알림**: "동선이 완성됐어요"
- [ ] 운영 장치: 사용자별 횟수 제한, 같은 입력 캐싱, 프롬프트 버전 관리, 실패 시 재시도, 비용 기록
- [ ] 개인정보처리방침에 AI 처리와 푸시 알림 내용을 추가한다

### 2-4. 회고

- [ ] 계획과 실제 비교 보기 (예정 시각 vs 실제 시각, 계획에 없던 장소)

**완료 기준:** 해외 여행도 장소를 검색해 계획할 수 있고, 인터넷이 끊겨도 여행 중 화면을 볼 수 있으며, AI가 만든 동선이 검증된 좌표로 생성돼 푸시로 알려 준다.

## 3단계. 공유 링크

- [ ] Route 53으로 도메인 연결
- [ ] 공유 링크 `https://<도메인>/trip/<공유ID>` 만들기, 공개 범위(링크가 있는 사람만 열람) 설계
- [ ] Android App Links: `assetlinks.json`을 S3 + CloudFront로 호스팅
- [ ] 앱이 없을 때 브라우저로 열리는 페이지가 기기를 판별해 스토어로 이동시킨다
- [ ] 앱에서 링크를 받으면 해당 여행 화면을 **읽기 전용**으로 연다 (로그인 필요, 편집 기능 숨김)
  - 보이는 것: 동선, 장소 설명, 사진
  - 숨기는 것: 메모 (서버 응답에서부터 빼서, 앱에 전달되지 않게 한다)
- [ ] **공유 끄기 / 링크 새로 발급**
  - 공유를 끄면 공유 ID를 비워 기존 링크가 열리지 않는다
  - 새로 발급하면 공유 ID를 바꿔 예전 링크는 막고 새 링크만 열리게 한다
- [ ] **내 여행으로 복사**
  - 서버: 공유 ID로 여행을 복사하는 API. Trip, Stop, Segment를 새로 만들고 출처를 "복사", 원본 Trip을 기록한다
  - 복사본은 원본과 연결하지 않고, "여행 전(계획)" 상태로 시작한다
  - 복사하는 것: 장소(이름, 좌표, 종류, 일차, 순서, 설명, placeId, 예정 시각), 구간(이동 수단, 곡률)
  - 복사하지 않는 것: 사진, 메모, 방문 체크, 실제 시각
  - 앱: 공유받은 여행 화면에 "내 여행으로 복사" 버튼. 복사가 끝나면 내 여행 목록에 추가되고 바로 편집할 수 있다

**완료 기준:** 링크를 누르면 앱이 있으면 해당 여행이 읽기 전용으로 열리고(메모 제외), 앱이 없으면 스토어로 이동한다. 공유를 끄거나 링크를 새로 발급할 수 있고, 공유받은 여행을 내 여행으로 복사해서 수정할 수 있다.
